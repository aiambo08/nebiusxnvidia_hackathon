| 2026-10-17 | The agent checkpoints FSM state, hysteresis counters, fault cooldowns (seconds left), the policy gate's executions of the last hour (ages) and the baseline into the event store's `kv` table (one key per camera, `agent_state:<camera_id>`, schema 1) on every state change, every SUSPECT window and every `storage.checkpoint_windows` windows, and on clean shutdown; `storage.restore_on_start` resumes it. Downtime (wall clock) counts as elapsed for cooldowns and rate limits. On restart every pending snapshot of this camera's incidents is rolled back (and counted as an execution); other cameras' snapshots and unknown actions are left pending. The event log, not the checkpoint, decides what is open: this camera's latest `incident` without a `closed` event resumes as NEEDS_HUMAN with no new plan or LLM call and closes after `exit_windows` healthy windows, so a checkpoint older than the last action can neither repeat nor reopen it; restore checkpoints at once so a second restart does not resume the older state. Unreadable, malformed, other-camera or other-schema state starts fresh. A failed restart rollback keeps the snapshot pending for the next start. One live agent per camera id and store: a heartbeat lease (`lease:<camera_id>`, refreshed every window, stale after `storage.lease_stale_s`, released on clean shutdown) makes a second agent with the same id refuse to start (`CameraInUseError`; `RA_CAMERA_ID` sets the id). The heartbeat is also refreshed before and after the planner call and before an action, `lease_stale_s` (default 60 s) must exceed planner `timeout_s` × `max_calls_per_incident` + the longest action timeout + one window (else a config error), and an agent that finds its lease taken over, missing or released logs `lease_lost`, stops checkpointing and never acts again (no LLM call either if it finds out before planning), and `run_live` then raises `CameraInUseError`. A clean shutdown leaves a released tombstone instead of deleting the lease, so a stalled agent cannot re-acquire a lease that the agent which took over has released. Residual: two agents starting in the same instant can both acquire (no compare-and-set); a wall clock stepped back by more than `lease_stale_s` keeps the camera locked until it passes the stored heartbeat. Known limits: a crash in HEALTHY loses up to `checkpoint_windows - 1` windows of baseline learning; on the first start against a pre-F5 DB the newest never-closed incident resumes as NEEDS_HUMAN (older ones are closed "superseded on restart") and heals after `exit_windows`; a snapshot whose restart rollback keeps failing is re-applied on a later start, possibly over settings a human changed since | F5 box: a restart must not lose the baseline or the hysteresis, nor repeat or leave half-applied an action whose verification never finished. Escalating instead of resuming VERIFYING avoids judging an action with lost before/after windows | Devin (Architecture + Safety) |
